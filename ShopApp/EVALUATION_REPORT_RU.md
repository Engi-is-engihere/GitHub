# ОТЧЕТ ОБ ОЦЕНКЕ ПРОГРАММЫ SHOPAPP

## Дата оценки: 2024
## Версия: 1.0

---

## 1. АРХИТЕКТУРА И СТРУКТУРА КОДА

**Оценка: 4/10**

### Положительные стороны:
- ✅ Логическое разделение на формы (Login, Register, Product, Basket, Admin)
- ✅ Использование WinForms с архитектурой Form.cs + Designer.cs
- ✅ Применение async/await в BasketForm

### Отрицательные стороны:
- ❌ Отсутствует слоистая архитектура (All-in-one в UI)
- ❌ Вся бизнес-логика в код-бихайнд формах
- ❌ Нет отдельного слоя для работы с данными (DAL)
- ❌ Глобальное состояние через класс Globals (антипаттерн)
- ❌ Нарушение принципа единственной ответственности (SRP)
- ❌ Отсутствует Dependency Injection

**Рекомендации:**
- Внедрить Repository Pattern для доступа к данным
- Создать сервисный слой для бизнес-логики
- Использовать DI-контейнер (например, Microsoft.Extensions.DependencyInjection)

## 3. БЕЗОПАСНОСТЬ

**Оценка: 6/10**

### Положительные стороны:
- ✅ Использование параметризованных SQL-запросов (защита от SQL Injection)
- ✅ Проверка существования пользователя перед регистрацией
- ✅ Разделение прав доступа (роли 1 и 2)

### Отрицательные стороны:
- ❌ Хранение паролей в открытом виде (no hashing)
- ❌ Строка подключения захардкожена в коде
- ❌ Нет шифрования чувствительных данных
- ❌ Отсутствие валидации входных данных
- ❌ Нет защиты от XSS
- ❌ Небезопасная обработка исключений (информация об ошибках видна пользователю)

**Критично:**
```csharp
// Пароли хранятся в БД в открытом виде!
string Selectq = "Select COUNT(id_user) FROM dbo.[User] Where [login] = @login and [password] = @password";
```

**Рекомендации:**
- Использовать хеширование паролей (BCrypt, Argon2)
- Извлекать connection string из конфигурации
- Внедрить валидацию входных данных

## ИТОГОВАЯ ОЦЕНКА: 5.0/10

### Резюме:

Программа **ShopApp** является рабочим приложением для управления онлайн-магазином одежды с базовым функционалом. Проект показывает понимание основных концепций программирования, но страдает от типичных проблем начинающих разработчиков: отсутствие архитектуры, нарушение принципов SOLID и безопасности.

### Ключевые проблемы:
1. **Безопасность**: Пароли хранятся в открытом виде
2. **Архитектура**: Нет разделения на слои
3. **Код**: Нарушение принципов, глобальное состояние
4. **Maintainability**: Сложно расширять и поддерживать

### Ключевые достоинства:
1. **Тестирование**: Отличное покрытие unit-тестами
2. **Базовый функционал**: Приложение работает
3. **Защита**: Используются параметризованные запросы

### Рекомендации по улучшению (приоритет):

**Критично (сделать немедленно):**
1. Хеширование паролей (BCrypt)
2. Извлечение connection string из конфигурации
3. Централизованная обработка ошибок
4. Использование Dispose для Graphics

**Высокий приоритет:**
1. Внедрить слоистую архитектуру (DAL, BLL, UI)
2. Логирование ошибок (NLog)
3. Валидация входных данных
4. Рефакторинг кода

**Средний приоритет:**
1. Внедрить DI-контейнер
2. Использовать Repository Pattern
3. Добавить документацию
4. Улучшить UI

**Низкий приоритет:**
1. Интеграционные тесты
2. UI-тесты
3. Производительность
4. Кэширование
